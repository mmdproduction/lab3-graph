# lab3-graph

Шаблонный мультиграф на C++20 с петлями и параллельными рёбрами.

```cpp
#include <string>
#include "Graph/Graph.hpp"

Graph<std::string, int, double> graph(false); // ID, данные вершины, вес
graph.add_vertex("assets", 10);
graph.add_vertex("textures", 20);

const auto first = graph.add_edge("assets", "textures", 2.5);  // индекс 0
graph.add_edge("textures", "assets", 7.0);                   // индекс 1
graph.add_edge("assets", "assets", 1.0);                     // петля

graph.set_edge_weight("assets", "textures", first, 3.0);
graph.remove_edge("assets", "textures", first); // индекс 1 становится индексом 0
graph.remove_edges("assets", "assets");         // удалить всю группу петель
```

## Хранение и идентификаторы

- Два собственных AVL-словаря: `ID → VertexData` и `EdgeKey<ID> → ArraySequence<Weight>`.
- В вершине нет информации о соседях. Выборки соседей просматривают словарь рёбер.
- `Graph<ID, VertexData, Weight>` принимает режим в конструкторе: `true` — ориентированный, `false` — неориентированный.
- Все ID задаются явно. Числа, строки и пользовательские типы допустимы; `0` и пустая строка не зарезервированы.
- Концепт `ComparableVertexId` проверяет копирование, конструирование по умолчанию и наличие `<` с результатом, приводимым к `bool`. Первые два условия нужны собственным контейнерам.
- `<` должен задавать стабильный строгий слабый порядок. Это семантическое требование нельзя доказать концептом. ID считаются одинаковыми, если ни один не меньше другого; `operator==` у типа ID не обязателен. Значения с нарушением порядка, например `NaN`, не используйте как ID.
- `VertexData` и `Weight` также должны поддерживать конструирование по умолчанию, копирование и присваивание.

## Рёбра и петли

- Для неориентированного графа пара ID нормализуется по `<`: обе записи направления обращаются к одному массиву.
- `add_edge(from, to, weight)` добавляет ещё одно ребро и возвращает его индекс в массиве. Одинаковые веса допустимы.
- `get_edge_weights(from, to)` возвращает весь массив как константную ссылку.
- `get_edge_weight(from, to, index)`, `set_edge_weight(from, to, index, weight)` и `remove_edge(from, to, index)` работают с одним ребром.
- Индекс — позиция в массиве, а не постоянный ID ребра. После удаления последующие индексы уменьшаются.
- `remove_edges(from, to)` удаляет весь массив. При удалении последнего отдельного ребра ключ пары тоже удаляется.
- `edge_count()` считает отдельные рёбра; `edge_count(from, to)` — рёбра между указанными вершинами, 0 для отсутствующей пары.
- `edge_keys()` возвращает каждую пару один раз. Для перечисления всех рёбер переберите также её массив весов.

`get_neighbors(id)` и `get_predecessors(id)` возвращают уникальные ID. В ориентированном графе это исходящие и входящие связи соответственно; в неориентированном выборки совпадают. При наличии петли ID самой вершины присутствует в выборке один раз.

Степени учитывают кратность рёбер. Ориентированная петля добавляет 1 к входящей и 1 к исходящей степени; `degree` — их сумма. Неориентированная петля добавляет 2 к степени; `degree`, `in_degree` и `out_degree` в этом режиме совпадают.

## Вершины и общие операции

- `add_vertex(id, data)`, `contains_vertex`, `get_vertex`, `set_vertex`, `remove_vertex`.
- Удаление вершины удаляет все инцидентные рёбра, включая петли и параллельные связи.
- `vertex_ids`, `vertex_count`, `empty`, `is_directed`, `clear_edges`, `clear`.
- Копирование и присваивание создают независимые графы; `swap` меняет их содержимое и режимы.
- Отсутствующий элемент или неверный индекс при чтении, изменении и удалении — `std::out_of_range`; повторный ID при вставке — `std::invalid_argument`.
- Выборки ID/ключей возвращают независимые собственные `ArraySequence`. Ссылки на веса не сохраняйте после изменения соответствующей группы, удаления вершины, очистки или присваивания графа. Изменение данных вершины заменяет словарь вершин и инвалидирует ссылки на его значения.
- Граф не синхронизирует одновременный доступ из нескольких потоков.

## Сложность и исключения

Обозначим число вершин как `V`, число непустых пар как `P`, сумму ёмкостей массивов весов как `C`, ёмкость выбранного массива как `c`.

- Поиск вершины — `O(log V)`, пары — `O(log P)`, веса по индексу — `O(log P)`.
- Общее число рёбер — `O(P)`; число рёбер одной пары — `O(log P)`.
- Соседи и степень — `O(log V + P)`, без копирования весов.
- Изменение, добавление или удаление одного веса в существующей группе копирует её массив: `O(log P + c)`; добавление также проверяет вершины за `O(log V)`.
- Изменение данных вершины копирует словарь вершин: `O(V)`.
- Удаление вершины копирует словарь рёбер, затем удаляет инцидентные пары: `O(log V + P + C + d log P)`, где `d` — число таких пар.
- Копирование всего графа — `O(V + P + C)`. Стоимость пользовательских копирований и сравнений здесь считается постоянной.

Копии при изменениях нужны для сохранения исходного состояния при исключениях во время подготовки. Затем подготовленный массив/словарь применяется через `swap`.

## Очередь и обход в ширину

Добавлены собственные контейнеры:

- `Sequence/LinkedList/LinkedList.hpp` — односвязный список с `head`, `tail` и счётчиком элементов. `append` и `remove_at(0)` занимают `O(1)`, произвольный доступ — `O(n)`.
- `Sequence/ListSequence/ListSequence.hpp` — реализация `Sequence<T>` поверх списка.
- `Queue/Queue.hpp` — FIFO-очередь поверх `ListSequence`, методы `enqueue`, `dequeue`, `front`, `size`, `empty`, `clear` и `swap`.

`dequeue()` только удаляет первый элемент. Чтобы получить его, сначала прочитайте `front()`. `front()` и `dequeue()` пустой очереди выбрасывают `std::out_of_range`. Добавление в очередь и удаление из неё занимают `O(1)` без учёта пользовательского копирования/разрушения значения.

Список, последовательность и очередь копируются независимо; перемещение оставляет источник пустым и пригодным для повторного использования. Список не требует конструктора по умолчанию или присваивания у элементов — достаточно копирования при добавлении. Очистка списка итеративная.

```cpp
#include "Graph/Graph.hpp"

Graph<std::string, int, double> graph(false);
graph.add_vertex("A", 1);
graph.add_vertex("B", 2);
graph.add_vertex("C", 3);
graph.add_edge("A", "B", 5.0);
graph.add_edge("B", "C", 1.0);
const auto order = graph.BFS("A");
// order: A, B, C
```

`Graph::BFS(start)` — константный метод графа. Он возвращает `ArraySequence<ID>` с порядком посещения достижимых вершин. Использует свою очередь и AVL-словарь посещённых ID. Вершина помечается при добавлении в очередь, поэтому циклы, петли и параллельные рёбра не приводят к повторным посещениям. В ориентированном графе обход следует исходящим связям. Веса игнорируются; это обход по слоям, поиск пути минимального веса здесь не реализован. Отсутствующий начальный ID вызывает `std::out_of_range`.

Граф передаётся по константной ссылке и не изменяется. На текущем хранении получение соседей просматривает все пары рёбер, поэтому стандартная оценка BFS `O(V + E)` для списков смежности здесь неприменима. Очередь, посещённые ID, результат и временная выборка соседей занимают `O(R)` памяти, где `R` — число достижимых вершин, без учёта внутреннего стека обхода AVL размером `O(log P)` для `P` непустых пар.

Тесты в `Tests/SequenceQueueTests.cpp` и `Tests/GraphAlgorithmsTests.cpp` включены в общую цель `graph_tests` и доступны через CTest.

## Обход в глубину

```cpp
const auto dfs_order = graph.DFS("A");
```

`DFS(start)` — константный метод графа, возвращающий `ArraySequence<ID>` с порядком посещения достижимых вершин. Обходит исходящие связи ориентированного графа, игнорирует веса, допускает петли и параллельные рёбра. Отсутствующий начальный ID вызывает `std::out_of_range`.

Реализация итеративная: собственный `Stack` на `ListSequence` заменяет рекурсию. В список добавлена операция `prepend`; `push`, `pop` и `top` стека работают с его началом за `O(1)`. `pop` только удаляет элемент; `top` и `pop` пустого стека выбрасывают `std::out_of_range`. Копирование и перемещение устроены так же, как у очереди.

Соседи помещаются в стек в обратном порядке, вершина помечается при извлечении. Результат совпадает с рекурсивным DFS, который перебирает соседей по возрастанию ID. В стеке могут временно находиться повторные записи вершины; повторно извлечённые посещённые вершины пропускаются, каждая вершина обрабатывается один раз.

Служебная память — `O(R + P)`, где `R` — число достижимых вершин, `P` — число непустых пар рёбер. Как и в BFS, получение соседей просматривает словарь пар, поэтому стандартная оценка `O(V + E)` для списков смежности здесь не применяется.

## Топологическая сортировка

```cpp
const auto order = graph.TopologicalSort();
```

Метод `const` использует алгоритм Кана: считает входящие рёбра, кладёт вершины с нулевой входящей степенью в собственную очередь, затем убирает их зависимости. Кратность параллельных рёбер учитывается и при подсчёте, и при уменьшении степени.

Возвращает `ArraySequence<ID>` со всеми вершинами, включая изолированные и несвязные компоненты. Для каждого ребра `from → to` его начало расположено раньше конца. Веса не используются. Порядок допустимый, но не обязательно лексикографически минимальный.

Неориентированный граф вызывает `std::invalid_argument`. Цикл, включая петлю или цикл в отдельной компоненте, вызывает `std::domain_error`. Пустой ориентированный граф даёт пустую последовательность. Граф не изменяется.

## Кратчайшие пути

```cpp
const auto path = graph.Dijkstra("A", "C");
// Или: graph.BellmanFord("A", "C")
if (path.reachable) {
    const auto& ids = path.vertices; // A, ..., C
    const auto weight = path.total_weight;
}
```

Оба метода `const` возвращают простую структуру `PathResult<ID, Weight>`:

```cpp
ArraySequence<ID> vertices;
Weight total_weight{};
bool reachable = false;
```

Если путь существует, массив включает начальную и конечную вершины, `total_weight` содержит его стоимость. При совпадении концов возвращается одна вершина с весом 0, если алгоритм не обнаружил ошибку. Для недостижимой цели `reachable == false`, массив пуст, значение веса не используется. Несуществующий начальный или конечный ID вызывает `std::out_of_range`.

Работают ориентированные и неориентированные графы, петли и параллельные рёбра. Рассматриваются все веса каждой пары, поэтому выбираются наиболее дешёвые связи. При равной стоимости найденный предшественник сохраняется. Результат владеет копией пути и остаётся независимым после изменений графа. Постоянные поля графа не дополняются индексами или списками соседей.

`Dijkstra` выбирает ближайшую необработанную вершину простым просмотром словаря расстояний, без кучи. Отрицательный вес в любой части графа вызывает `std::invalid_argument`.

`BellmanFord` делает до `V - 1` проходов релаксации и затем проверяет возможность дальнейшего улучшения. Отрицательный цикл, достижимый из начала, вызывает `std::domain_error`, даже если он не ведёт к выбранной цели. Недостижимый отрицательный цикл игнорируется. В неориентированном графе достижимое отрицательное ребро образует отрицательный цикл.

Концепт `NumericPathWeight` разрешает стандартные целочисленные типы, кроме `bool`, и вещественные типы. С другими весами граф, BFS, DFS и топологическая сортировка доступны, а методы кратчайшего пути исключаются ограничением `requires`. `NaN` и бесконечные веса в любой части графа отвергаются обоими алгоритмами (`std::invalid_argument`). Вещественные вычисления используют обычную арифметику выбранного типа и строгое сравнение без допуска.

«Бесконечность» для недостижимых вершин не хранится, поэтому максимальное представимое значение может быть корректным расстоянием. Если сумма при вычислении промежуточного кандидата выходит за диапазон `Weight`, выбрасывается `std::overflow_error`; эта ошибка может возникнуть раньше диагностики отрицательного цикла. Граф при исключениях не изменяется.

При `V` вершинах, `P` непустых парах и `E` отдельных рёбрах верхние оценки времени для текущего хранения: Дейкстра — `O((V² + E) log V + VP)`, Беллман–Форд — `O(VE log V)`, топологическая сортировка — `O(VP + (V + P) log V)`. Копирование значений и сравнение ID считаются постоянными. Все три алгоритма используют `O(V)` дополнительной памяти.

## Краскал: минимальный остовный лес

```cpp
const auto forest = graph.Kruskal();
for (std::size_t i = 0; i < forest.edges.size(); ++i) {
    const auto& edge = forest.edges.get(i);
    // edge.from, edge.to, edge.weight
}
// forest.total_weight, forest.component_count
```

`Kruskal()` — константный метод для неориентированного графа с весами, удовлетворяющими `NumericPathWeight`. Возвращает `SpanningForestResult<ID, Weight>`: собственную последовательность выбранных рёбер `WeightedEdge<ID, Weight>`, общий вес и число компонент. Рёбра результата содержат копии концов и выбранного веса; это снимок, а не ссылка или постоянный идентификатор ребра исходного графа.

В связном непустом графе получается минимальное остовное дерево с `V - 1` ребром. В несвязном графе получается минимальный остовный лес: отдельное дерево в каждой компоненте, включая изолированные вершины; число рёбер равно `V - component_count`. Для пустого графа все значения нулевые. Минимизируется сумма весов всех выбранных рёбер, а не путь от одной вершины до другой.

Алгоритм собирает отдельные параллельные рёбра, пропускает петли и сортирует кандидатов по весу собственной пирамидальной сортировкой. Равные веса упорядочиваются по концам ребра, чтобы результат был воспроизводим. Ребро добавляется только при соединении разных компонент; иначе оно создало бы цикл.

Собственная `graph_detail::DisjointSet` хранит родителей и ранги в `DynamicArray`, объединяет по рангу и сжимает пути при поиске представителя. Временный AVL-словарь переводит любые допустимые ID в индексы массивов. ID графа остаются шаблонными, а соседи в вершины не добавляются.

Отрицательные и нулевые веса допустимы. Ориентированный граф вызывает `std::invalid_argument`; `NaN` и бесконечные веса отвергаются во всём графе, включая петли. Общий вес складывается с проверкой диапазона: непредставимая промежуточная сумма вызывает `std::overflow_error`, даже если последующие положительные слагаемые вернули бы итог в диапазон. При исключениях исходный граф не меняется.

При `V` вершинах и `E` отдельных рёбрах время — `O(V log(V + 1) + E log(E + 1) + E log(V + 1))`, дополнительная память — `O(V + E)`. Здесь учтены сортировка и обращения к AVL по ID; операции системы множеств с объединением по рангу и сжатием путей занимают амортизированное `O(α(V))`. Сравнение и копирование ID/веса считаются постоянными.

## Жадная раскраска вершин

```cpp
const auto coloring = graph.GreedyColoring();
const std::size_t color = coloring.colors.get(vertex_id);
// coloring.color_count — число использованных цветов
```

`GreedyColoring()` — константный метод, возвращающий `ColoringResult<ID>`: собственный AVL-словарь `colors` с соответствием ID → номер цвета и счётчик `color_count`. Цвета — целые числа начиная с 0; интерфейс может сопоставить им реальные цвета.

Вершины обрабатываются по возрастанию ID. Для каждой вершины отмечаются цвета уже раскрашенных соседей, затем выбирается минимальный свободный номер. Массив отметок использует номер текущего шага, поэтому его не требуется очищать перед каждой вершиной. Пустой граф использует 0 цветов, непустой граф без рёбер — 1.

Любое ребро запрещает одинаковый цвет у его концов, независимо от направления. Веса и кратность рёбер не влияют на результат. Петля делает правильную раскраску невозможной и вызывает `std::domain_error`. Поддерживаются любые типы весов, допустимые для самого графа, в том числе нечисловые. Результат — независимая копия; исходный граф не меняется.

Минимальное число цветов не гарантируется: результат зависит от порядка вершин. Например, путь `0 — 2 — 3 — 1` можно раскрасить двумя цветами, но порядок `0, 1, 2, 3` даёт цвета `0, 0, 1, 2` и использует три. При максимальном числе различных соседей `Δ` алгоритм использует не более `Δ + 1` цветов.

При `P` непустых парах рёбер текущая реализация просматривает словарь пар для каждой вершины: время `O(VP + (V + P) log(V + 1))`, дополнительная память `O(V)`. Стандартная оценка для списков смежности здесь неприменима. Параллельные веса не перебираются.
